把几十家免费大模型收成一个端点：FreeLLMAPI 实战

  • 2026-10-27
  • 作者 konb
  • ~2.30K 字
  • 次阅读
  • 条评论

本文最后编辑于 前，其中的内容可能需要更新。

写 AI 辅助编程的人，多半都干过同一件事：到处薅免费额度。薅着薅着就发现，免费额度最稀缺的从来不是”模型不够好”，而是”这条通道随时会断”。今天这家限流，明天那家要登录，后天发现 key 过期了。于是我一直在找一个能把这些散装通道收拢成一个口子的东西——后来找到了 FreeLLMAPI。

它是什么

FreeLLMAPI 是一个 MIT 协议的开源项目，官网在 freellmapi.co。按仓库自己的说法，它聚合了 34 家提供免费额度的大模型厂商、635 个免费模型端点，对外只暴露一个 OpenAI 兼容的 /v1 接口。

它干的事拆开看就四件：

  1. 收口。各家厂商的接口格式千奇百怪，它统一成 OpenAI 那套 base_url + api_key + model 的调用方式。换模型不用改代码，改个 model 字段就行。
  2. 智能路由。同一个模型可能在好几个上游都有，按可用性和延迟挑一条。
  3. 自动故障转移。这条挂了自动切下一条，不用人肉盯着重试。
  4. 加密存储上游 key。key 落在本地数据目录里，不是明文躺在配置文件里。

需要提醒的是，仓库自述是”个人实验用，非生产”。这点很实在：它依赖的全是免费额度池，免费额度一变，说没就没。别拿它扛线上业务。

装起来

它既有桌面版，也能自己部署。桌面版装完之后数据都在 AppData\Roaming\FreeLLMAPI\ 下：一个 SQLite 存 provider 和 key，一个 config.json，一个 .encryption-key，还有 logs\freeapi.log。默认监听 3001 端口，浏览器打开就是管理面板。

面板里要做的事很简单：把各家的 key 填进去，模型列表会自动拉。填完先别急着干活，先拿一条最小请求量一测——这一步能省你后面一小时的血压。

真正坑人的地方

坑不在安装，在上游。

免费额度会缩水成一把钥匙。 我这台机器上跑着的时候，聚合网关里几十个 provider，最后真正可用的上游只剩下一把免费 key。这把 key 本身还带限流：每分钟只放行一个请求。

这个限制对聊天无所谓，对 agent 是致命的。agent 干活是一步一等一步的：读文件是一次请求、调工具是一次请求、写文件又是一次请求。每一步都刚好撞在”每分钟一个”的闸门上，于是每一步都被拒，一路拖到超时。我第一次遇到的时候以为是自己脚本写错了，排查半天才发现是上游在数秒。

所以要先量速率，再派重活。 判断标准很简单：拿一个最小请求连续打几次，如果第 N 次开始排队或报错，那就是限流在起作用，这时候往里灌长任务就是纯烧时间。

模型质量参差得厉害。 池子里什么都有，但能写代码的和只会寒暄的混在一起。别看名字挑——先丢一个真实小任务试试，这家的模型写出来的东西能不能用，一试便知。

key 虽然加密存了，但终究在本机。 别把 key 写进仓库、写进文章、写进任何会被提交的地方。免费额度丢一次不心疼，私有仓库泄了才叫事。

端口会撞。 3001 不是什么冷门端口，本机要是已经有东西在监听，改端口比排查半天省事。

我的用法建议

我会这么分工：

  • 读文件、查资料、试命令这类短平快的活，丢给免费池子，额度不值钱但量够。
  • 写长文、改大段代码、需要连续十几步推理的活，老实走付费额度。免费池子那点配额撑不住一个完整的长任务。
  • 不管走哪条道，派活之前先跑一条最小请求，确认通道是通的、速率是能接受的。

FreeLLMAPI 真正的价值不是”免费”，而是把散落在十几个地方的免费通道收成一张能查、能测、能切的地图。地图有了，什么时候该省、什么时候该掏钱，就自己说了算。
