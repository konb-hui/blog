在 Windows 上给 AI 装一套趁手的工具箱

  • 2026-10-28
  • 作者 konb
  • ~2.44K 字
  • 次阅读
  • 条评论

本文最后编辑于 前，其中的内容可能需要更新。

给 AI 装工具这件事，我踩的坑比装的工具多。装完打印一行 success，第二天要跑的时候发现路径不对、显卡没吃到、端口被占，这类事发生过不止一次。这篇不复述安装步骤，只写我现在怎么挑、怎么装、怎么验收，以及哪些折腾我后来放弃了。

先看盘，再看需求

我这台机器 C 盘只剩五点几 G，D 盘空着两百多 G。这个数字决定了后面所有的选择：任何上 G 的东西都不许落在 C 盘。

所以动手前先量三样东西。目标盘还剩多少，显卡是什么型号，系统 Python 是什么版本。我的情况是 RTX 3060 Laptop、系统 Python 3.14.7、Node 24。量完才知道该选哪个安装包——显卡是 N 卡就走 CUDA 版，系统 Python 太新就用自带解释器的便携版，避开一堆轮子还没跟上 3.14 的麻烦。

顺序反过来就很容易白干：先兴冲冲装了源码版，卡在编译，最后发现官方本来就有打好包的便携版。

挑工具：看它约束你什么

我判断一个工具值不值得装，主要看它的约束条件，而不是功能列表。要什么显卡、什么 Python 版本、占多大、开哪个端口、要不要管理员权限，这五项决定了它能不能在我的机器上活下来。

ComfyUI 最后选的是 NVIDIA 便携版，一点九 G，自带 Python 3.12 和 CUDA 版 torch，跟系统那个 3.14 完全隔离。这个隔离很关键：它不会污染我其他项目，我也不用为了它去降级系统解释器。

浏览器自动化那两个项目走了另一条路。browser-use 和它的加速版都是 Python 包，我没往系统环境里装，而是用 uv 单独开项目，Playwright 复用已经装好的 Chrome 和 Edge，省掉再下一份浏览器的流量。密钥统一放项目里的 .env，并且确认 .gitignore 里有它——这一步比装包本身重要。

还有一种需求我现在会先挡一下：顺手做个工具。比如让人写个能按游戏分类下 mod、还把英文描述翻成中文的小工具。听起来不难，但抓取规则会变、翻译要配额、安装路径每个游戏都不一样，维护成本远高于省下的那几分钟。判断标准很土：这活我一年干几次。超过十次才值得写成工具，只干一两次，用现成的东西加手工拼一下更快。

解压工具也是同一个道理。我不想为了一个压缩包去官网翻下载页，直接用 winget 一条命令装 7-Zip，几秒钟的事。这类基础设施越少折腾越好。

装：把长动作切成能收尾的小段

这是我最贵的一课。我那条流水线有个硬限制：连续十分钟没有任何输出，进程直接被杀掉，而且不自动重试。第一次装 ComfyUI，我用一条命令下那一点九 G，跑到一半被杀，前面全废；第二次重试还是同样的死法。

改成小段下载之后就没再失败过。用系统自带的 curl，每条命令带断点续传和五十五秒上限，跑完一段就看一眼当前大小，报个百分比，再跑下一段。网络慢的时候单段会提前结束，文件仍然可用，下次从断点接着写。同一个命令重复执行是幂等的，被杀几次都无所谓。

下完先校验 SHA256，对得上才解压。解压也不一次解完，先列一遍压缩包结构，按顶层目录分批解，每批几十秒。整套动作慢，但没有一步会卡住整轮。

验收：看服务，别看日志

装完那一刻的自检最容易骗人。pip show 有输出不代表能跑，解压成功不代表能启动。

我的验收标准统一成三条：进程能起来、端口能通、真实请求有正确返回。ComfyUI 是打开本地 8188 端口，请求一下系统信息接口，能拿到显卡和版本才算过。浏览器自动化是两个项目各跑一个真实页面，用无害的示例站，确认动作链真的执行了、返回结构对得上。缺一条我就当没装成。

这套标准救过我一次：某次包确实装上了，但 Playwright 的浏览器内核没下，import 一切正常，一跑就报找不到可执行文件。只看到 success 的话，这坑要等到用的时候才炸。

验收完还要顺手记下四件事：装在哪、怎么启动、开哪个端口、怎么关。少记一件，下次用的时候就要重新翻文档，甚至重新装一遍。我为 ComfyUI 记的是安装目录、那个启动 bat 的路径、8188 端口，以及关掉服务就是关掉窗口——顺带提醒自己别直接断电式关机，模型加载到一半被打断，下次启动会报缓存错。

多套环境并存，靠隔离而不是靠记性

机器上现在有系统 Python 3.14、便携版自带的 3.12、uv 管的几个项目环境，还有 Node。想让它们不打架，我的规矩很简单：谁需要特殊版本，谁自带解释器；能用项目级环境就不用全局；大体积的东西一律装非系统盘。

代价是启动命令不统一。有的点 bat，有的 uv run，有的先激活环境。我现在的做法是把每个工具的启动方式和端口写进一张自己的备忘表，不然过两周真的会忘。这个表比任何自动化都实用。

目录也要有约定。我的规矩是 D 盘下按项目名一个文件夹，深度不超过两层，名字用英文，别带空格。中文路径和空格是各种脚本静默失败的高发区，尤其是那些把路径拼进命令行的地方，报错还看不懂。

哪些折腾其实不值得

清理 C 盘就是典型。列清单、分辨哪些缓存能删、哪些是系统文件不能碰，做完提上来的空间可能还不够装一个模型。真正解决问题的是把大件挪到 D 盘，清理只是止疼。所以现在我的顺序是先改安装位置，再谈清理。

另一类是对抗系统设计。我查过一个游戏启动器为什么老弹 UAC，结论是：游戏内容更新确实不需要管理员，装在非 Program Files 的盘上、目录对普通用户可写就行；但启动器自更新和反作弊驱动安装的程序清单本身就要求提权，这部分绕不过去，也不该绕。判断依据是程序清单和目录权限，不是猜。搞清楚之后我就不再折腾了，看到 UAC 点一下确认，比找绕过办法省事得多。

最后一类是不追最新。版本号大不等于好用，能稳定跑起来、出了问题查得到资料，比多两个新特性重要。工具是拿来干活的，不是拿来养的，装完能跑、用得顺手，就该停手了。
