在 Windows 上给 AI 装一套趁手的工具箱

  • 2026-10-28
  • 作者 konb
  • ~3.11K 字
  • 次阅读
  • 条评论

本文最后编辑于 前，其中的内容可能需要更新。

装完一个工具，看到日志末尾那行打印 success。大多数人的动作是关窗口。我这么干过很多次。下一次真正要用它的时候，才发现路径不对。端口不通，显卡根本没被用上。安装成功和可以使用，中间隔着一整套验收。

最典型的一次是浏览器自动化。包确实装上了，pip show 有输出，import 也不报错。一跑就提示找不到浏览器可执行文件。Playwright 的内核压根没下载。只看日志的话，这个坑会一直埋到真正要用它的那天。

所以这篇不写安装步骤。写我现在怎么挑、往哪放、怎么验收。再说哪些折腾后来干脆不做了。

第一步：先量机器，再看功能列表

我这台机器 C 盘只剩 5.8 GB，D 盘空着 214 GB。这个数字比我想要什么功能重要得多。任何上 GB 的东西落在 C 盘，系统就报警。

动手前我只量三样：目标盘剩多少、显卡是什么型号、系统解释器什么版本。我的是 RTX 3060 Laptop、Python 3.14.7。Node 版本 24.16.0。量完答案基本就出来了：N 卡走 CUDA 版。系统 Python 太新，一堆轮子还没跟上，就选自带解释器的包。

这三个数还会互相牵制。显卡决定能不能吃 CUDA，解释器版本决定哪些包装得上。盘位决定能装多大的东西。任何一项没量，后面都得返工。

现在我判断一个工具值不值得装，只问五个问题。要什么显卡、要什么解释器版本、装完占多大。还要看开哪个端口、要不要管理员权限。功能列表放在后面看。这五项里只要有一项在我的机器上过不去，功能再多也白搭。五项过一遍再下载，比装完返工省事。

ComfyUI 我选的是 NVIDIA 便携包，1,925,204,508 字节。自带 Python 3.12 和 CUDA 版 torch。它和系统那个 3.14 完全隔离。我不用为它降级，它也不会污染别的项目。

顺序反过来就很容易白干。先兴冲冲装了源码版，卡在编译。回头才发现官方早就把包打好放在 Release 里。

第二步：能让它自带的，就别动全局环境

browser-use 和它的加速版都是 Python 包。我一个都没往系统环境里装。用 uv 各开一个项目，依赖锁在项目里，跑的时候 uv run。不想要了，文件夹删掉就行。

Playwright 的浏览器也没重新下一份。直接复用机器上装好的 Chrome 和 Edge。省下的不只是几百兆流量，还有“两个浏览器版本对不上”这类排查。

密钥统一放项目里的 .env，同时确认 .gitignore 里真有这一行。这一步比装包本身重要。装错了可以重装，密钥推上去就收不回来了。版本也别写浮动的最新，依赖锁死。半年后回来，还能装出同一套东西。

大件一律放 D 盘。便携版解压到 D:\ComfyUI_windows_portable。其他项目放 D:\ 下按名字建的文件夹。深度不超过两层，名字用英文，不带空格。中文路径和空格是各种脚本静默失败的高发区。尤其是把路径拼进命令行的那些，报错还看不懂。

代价是启动方式不统一。有的双击 bat，有的 uv run，有的要先激活环境。这个没法统一，只能靠记。

第三步：把长动作切成五分钟能收尾的小段

这是我最贵的一课。我那条流水线有个硬限制。连续十分钟没有任何输出，进程直接被杀，而且不自动重试。

第一次装 ComfyUI，我用一条命令下那 1.9 GB。跑到一半被杀，前面全废。第二次重试，同样的死法，文件停在一半，下一轮还得从头开始。

改成小段之后就没再失败过。命令是 curl -C - --max-time 55。-C - 负责断点续传。--max-time 55 保证每条命令 55 秒内必然结束。网络慢的时候单段会提前截断，文件仍然可用。下一段从断点接着写。重复执行是幂等的，被杀几次都无所谓。每跑完一段就看一眼文件大小，算个百分比，再跑下一段。

断点续传有个前提，同一个文件同一时间只能有一个进程在写。动手前先确认，没有残留的 curl 还在跑。

下完先校验 SHA256，和发布页那串对上才解压。这一步花十几秒，能挡掉镜像不同步和下载截断。

7-Zip 得在下载之前就装好。不然 1.9 GB 的包下完也打不开，等于白等一轮。

解压也不一次解完。先用 7z l 列一遍结构，再按顶层目录分批 7z x，每批一个目录。整套动作很慢，但没有一步会卡住整轮。顺带说一句，7-Zip 我是用 winget 装的，几秒钟。没去官网翻下载页。分段的代价是多敲几次命令，换来的是随时能停。

第四步：验收只看三件事

装完那一刻的自检最容易骗人。pip show 有输出不代表能跑，解压成功不代表能启动。

我的验收标准只有三条：进程能起来、端口能通、真实请求有正确返回。ComfyUI 打开本地 8188 端口，请求 /system_stats 这个系统信息接口。能拿到显卡型号和版本号，才算过。

浏览器自动化那两个项目各跑一个真实页面。页面用 example.com 这种无害站点。确认动作链真的执行了，返回结构对得上。

缺一条我就当没装成。前面那个 Playwright 内核没下的例子，就是卡在第三条上暴露的。前两条是门槛，第三条才是证据。端口这条还要先看有没有被占。8188 上如果已经有别的进程在听，服务根本起不来。日志里往往只有一行不起眼的报错。

验收完顺手记四件事：装在哪、怎么启动、开哪个端口、怎么关。少记一件，下次用就要重新翻文档。

我给 ComfyUI 记的是安装目录、run_nvidia_gpu.bat 的路径、8188 端口，关服务就是关窗口。还加了一句提醒：别在模型加载到一半的时候直接断电式关机。下次启动会报缓存错。三条都过，才算能写进备忘表。

哪些折腾可以早点放弃？

清理 C 盘是典型。列清单、分辨哪些缓存能删、哪些是系统文件不能碰。做完能提上来的空间，可能还不够装一个模型。真正解决问题的是把安装位置改到 D 盘，清理只是止疼。现在我的顺序是先改位置，再谈清理。

自己写小工具也要先挡一下。有人想要一个按游戏分类下 mod、把英文描述翻成中文、还能本地安装的工具。听着不难，但抓取规则会变，翻译要配额。每个游戏的安装路径还不一样。我的判断标准很土：这活我一年干几次。超过十次才值得写成工具，一两次就用现成的东西加手工拼。

对抗系统设计更不值得。我查过一个游戏启动器为什么老弹 UAC。游戏装在 F 盘根目录，整个目录树对普通用户可写。主程序和启动器的嵌入清单都是 asInvoker。所以日常下载更新确实不需要管理员。但启动器自更新程序 NTEUpdate.exe 的清单写的是“必须管理员”。反作弊驱动又装在 C 盘的 AntiCheatExpert 目录下。这两处绕不过去，也不该绕。

先看清单，再看目录权限。两样都有结论了，再决定要不要提权。搞清楚之后我就不折腾了。看到 UAC 点一下确认，比找绕过办法省事。

追最新版本也没必要。版本号大不等于好用。能稳定跑、出了问题搜得到资料，比多两个新特性重要。我现在的做法是版本能用就不动，除非它挡了某个必须的功能。

复盘：

  1. 装完先发一个真实请求，通过再关窗口。日志里的 success 只当参考。进程、端口、返回值三个都对上才算装成。
  2. 选型先写清显卡、解释器、体积、端口、权限五项。任何一项不合就排除，不靠试用碰运气。
  3. 预计超过五分钟的下载或解压，一律切成带断点续传的小段。做完一段，校验一段，宁可多敲几次命令。
  4. 装完立刻记下位置、启动方式、端口、关闭方法。顺手写一句“这东西以后不再折腾”，下次直接用。
